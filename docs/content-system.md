# Content and application reference

Implementation notes moved out of the mandatory agent entry point. Use [AGENTS.md](../AGENTS.md) to choose a task scope, then read the relevant section here. An accepted ADR is a decision and may include deferred phases; these notes are not whole-product acceptance. Verify the shared schema, writer, public reader and tests before relying on a behavioral claim.

Paths starting with `app/`, `server/`, `shared/` or `public/` are under `apps/web-app/`; other paths are relative to the repository root. Fixture and deployment details are in [development.md](development.md).

Routes and quests currently show editorial content and visit points. Saved visit progress and quest completion are not implemented. Offers claim/redemption and billing remain future phases in ADR 0017; their tables and presentation do not complete the transaction flow.

## Architecture

Monorepo (pnpm):

- `apps/web-app`: Nuxt 4, Reka UI (headless only), `@nuxtjs/seo`, `nuxt-auth-utils`. Styling is local CSS tokens, not Tailwind and not `@nuxt/ui`. See ADR 0010 and `docs/design-system.md`. Place photos are processed with `sharp` (ADR 0011): master plus AVIF/WebP variants under `MEDIA_DIR/{id}/`. `<MediaImage>` is the public `<picture>`. Category SVG art is the fallback when a place has no cover. Moose mascot stickers: `docs/stickers.md` (`<Sticker>`). Food stickers for price-anchor cards: `docs/food-stickers.md` (`<Sticker set="food">`, `public/stickers/food/`, `shared/food-stickers.ts`).
- `packages/database`: Drizzle ORM and Postgres. Schema, repositories, SQL migrations, initial seed.
- `packages/types`: Zod schemas shared by the API.
- `packages/map`: `@k39/map`, the MapLibre map core (ADR 0019, ADR 0037).

Install icons: `icon-192.png`, `icon-512.png`, and `icon-maskable-512.png` (safe zone on `#F5EEE1`). Header moose: `logo/moose-head` (png and webp, 1x and 2x). The header moose and the social card are not produced by that script. Favicon, touch icon, and manifest URLs append `?v=` from that constant. The file names stay. There is no SVG favicon.

### Storage and bootstrap

Published pages are server-rendered from Postgres. Place body is markdown text in the database. See ADR 0007 and ADR 0008.

URLs: `/{slug}` for a place, `/forty` `/zamki` `/plyazhi` `/kurorty` `/muzei` `/eda` for hubs, `/marshruty/{slug}`, `/podborki/{slug}`, `/kvesty/{slug}`. Regions are not in the path. Old `/place/*` and `/quest/*` 301 in one hop. `/map` is the visitor map. `/map/forty` and `/karta` are not redirected. Details and the crawl rules are in ADR 0008. Search console setup is in `docs/search-consoles.md`.

On boot the Nitro plugin migrates, then `applyInitialContent()` inserts categories, the 27 fort pages, one route, one collection and the five-fort quest if `content_imports` does not already contain `initial-content-v1`. `initial-content-v2` then fills seeded slugs that are still empty drafts from the old catalog and publishes them. A later boot skips both. An empty `ADMIN_EMAILS` is fine: the site still serves public pages, and nobody is promoted to admin until that list is set. Later edits happen in `/admin` or through `POST`/`PATCH /api/content/places` and the MCP server. Those two entry points call the same place writer. Place, venue, route, collection, quest, hub, and passport saves go through `apps/web-app/server/utils/content/save.ts`: it normalizes the prose, runs the stop-list, writes the row, drops review hashes that no longer match, and enqueues changed sections. `CONTENT_API_TOKEN` is the editor bearer: it can publish and edit live content. `CONTENT_DRAFT_TOKEN` is the agent bearer: writes land as drafts or a pending review, and it cannot publish. Neither token can manage users or settings. Article text is not committed to this repo as drafts, seeds, or page files. `applyInitialContent` is the one-time bootstrap already recorded in `content_imports`. Do not add another.

`pnpm db:seed:fixtures` upserts test fixtures after migration. It is not boot content and not an article. Slugs: towns `fixture-town` (hub photo via place `fixture-town`) and `fixture-plain` (no photo); venues `fixture-cafe-photo` (photo, coordinates, three prices, schedule, Instagram, every venue module), `fixture-cafe-plain` (no photo, coordinates, prices, schedule), `fixture-cafe-peer` (third price for a band), `fixture-cafe-nocoords`, `fixture-cafe-open` (verified schedule with an opening time and no closing time, ADR 0042), `fixture-cafe-weekdays` (verified weekday hours, weekend hours unknown, ADR 0044), `fixture-cafe-seasons` (two seasons, a monthly closure, and an exception, so the venue forms show the hours read-only); places `fixture-stop`, `fixture-contact` (phone, website, schema subtype `Church`; public in the `muzei` hub once boot content exists), `fixture-museum` (ticket table, two upcoming events, one past and one cancelled event that never render, ADR 0046), and `fixture-tickets-stale` (only stale ticket rows); route `fixture-route` (both places as stops, its own ticket row); collection `fixture-modules` (every page module, `fixture-museum` among the items). Dated notices (ADR 0049), relative to the seed day: `fixture-cafe-photo` has a current relocation and an expired row, `fixture-cafe-plain` an upcoming `closed`, and `fixture-contact` a current `closed` and an upcoming renovation. The 32 price-catalog slugs are `PRICE_CATALOG` in `packages/database/src/seed/price-catalog.ts`. A second run updates those rows. Pages are `noindex`.

## Content MCP

Streamable HTTP: `https://k39.online/mcp` (`@nuxtjs/mcp-toolkit`, ADR 0012, ADR 0035). Same bearers as the content API. Missing or wrong token: 401 with `WWW-Authenticate: Bearer realm="k39"` and no OAuth metadata, so a cloud agent retries with the header configured on the MCP server. Both tokens unset: 503. Sixty calls per minute per secret. The editor token can publish, unpublish, and edit live places, routes, collections, quests, hubs, regions, and media. The draft token cannot publish, archive, or edit a published quest or listing. On a published or closed venue, venue_update, schedule_set for opening hours, and venue_prices_set stage allowed keys in content_drafts (ADR 0047). The editor applies them with content_set_publication; newer owner changes keep their keys pending. An archived venue refuses these writes. A draft-token write to a published place, route, or collection is stored in `content_drafts` and the public page stays. A draft-token photo write on a published or archived place or collection, or on a published, closed, or archived venue, is a 409. A schedule write on a published or archived place is also 409; a published or closed venue stages its opening schedule (ADR 0047). A draft-token `fact_update` is the same 409 when the fact's parent is live: a published or archived place or route, a stop on that route, a region, a published or closed venue, or a subject type the writer does not resolve. `venue_delete` is editor-only. `place_get`, `route_get`, `collection_get`, and `venue_get` return `pendingReview`. The update returns that stored draft: `pendingReview`, `bodyLength`, and `renderedFields`, plus ordered points or items for a route or a collection. An editor `content_set_publication` with `published` and no other fields applies the pending payload and then deletes the draft. `PATCH /api/content/places` uses the same writer. Every write is an `mcp_audits` row with actor `mcp`.

The owner issues `CONTENT_DRAFT_TOKEN` (`openssl rand -hex 32`), sets it on the web app, redeploys, and adds `https://k39.online/mcp` in Cursor Cloud Agents with `Authorization: Bearer <that value>`. Do not commit the value. Do not write it from an agent.

### Tool catalog and payloads

Tools: `places_list`, `place_get`, `place_draft_create`, `place_update`, `place_draft_update` (alias of `place_update`), `place_submit_review`, `content_set_publication`, `content_archive`, `hubs_list`, `hub_update`, `region_list`, `region_upsert`, `routes_list`, `route_get`, `route_draft_create`, `route_draft_update`, `route_update` (alias of `route_draft_update`), `collections_list`, `collection_get`, `collection_save`, `quests_list`, `quest_get`, `quest_save`, `quest_update`, `page_passport_get`, `page_passport_set`, `content_scores_list`, `content_score_get`, `content_score_preview`, `content_report_weekly`, `queue_list`, `fact_get`, `fact_confirm`, `fact_update`, `page_mark_reviewed`, `notices_get`, `notices_set`, `notices_list`, `personas_list`, `page_personas_get`, `page_personas_set`, `media_upload_from_url`, `media_attach_to_place`, `media_list_for_place`, `media_delete`, `commons_search`, `commons_import`, `content_guide`. The same guide is also a resource and a prompt. Omitting `publicationStatus` on an update leaves a published page published. `route_draft_create`, `route_draft_update`, and `route_update` accept ordered `points: [{placeSlug, note?}]` and an optional `path` of `[longitude, latitude]` pairs. Omit `path` to keep it. Null clears it. The map uses that line only for the selected route. `collection_save` accepts ordered `items` in the same shape. Each `placeSlug` must exist. Omitting the array leaves the current stops. `content_archive` hard-deletes a draft route or collection and archives a published or review row (the public URL returns 410). A draft route that a quest still links returns 409. `quest_save` and `quest_update` change that link with `routeSlug`, or `null` to clear it, so the draft can be deleted. `region_list` and `region_upsert` read and write regions (`slug`, `name`, optional `coordinates` or `center`). `regionSlug` is a slug from the regions table. Page passports and the 0-100 score are ADR 0016. `content_score_get` reads the stored score. `content_score_preview` scores a draft, a review page, or a pending place payload and does not write `content_scores`. ADR 0034 lets a justified passport raise a page ceiling to 20000 characters. Personas (ADR 0024): eleven codes in `shared/personas.ts`, page targets in `page_personas` with one primary per page; `/admin/content-scores` shows them and filters pages without a primary. Static coverage per persona (ADR 0025) is the page × persona table under the scores; text modules can declare a `role` for it. Offer delivery boundaries are recorded in [ADR 0017](adr/0017-geo-offers.md). The first Commons import on an empty place becomes the cover. A repeat import of the same Commons page on that place returns the existing photo. Venues (ADR 0018) use `venue_create`, `venue_update`, `venue_get`, `venues_list`, `venue_find_duplicates`, `venue_import_osm`, `venue_listing_intro_set`, `venue_listing_modules_set`, `venue_stats`, and `venue_delete`. `venue_delete` hard-deletes a draft or an archived venue and is editor-only. A published or closed venue stays. OSM import creates drafts and dedupes by `osmId`. It does not publish. A generated slug that clashes gains the town or district, then a number. Collection and venue photos use `media_attach_to_collection`, `media_detach_from_collection`, `media_list_for_collection` and `media_attach_to_venue` (ADR 0038 for collections). The shared price catalog is `price_items_list` and `price_item_upsert`, and `venue_price_bands_recompute` rebuilds the price bands of a town. Schedules (ADR 0028) use `schedule_get`, `schedule_set`, `schedules_list` and the one-off `schedules_migrate`. Ticket prices and dated events (ADR 0046) use `admission_get`, `admission_set`, `admissions_list`, `event_get`, `event_upsert`, and `events_list`. They write `admission_prices` and `calendar_events`, sync facts `admission` and `event`, and refuse a draft-token write on a live subject with 409. The daily `event-expire` job retires past events. `offers.venue_id` links an offer to a venue. `FEATURE_SPONSORED_VENUES` defaults off in `.env.example` until a partner slot should lead «Где поесть рядом».

### Tool implementation

`@nuxtjs/mcp-toolkit` treats every file directly under `server/mcp/` as a handler (plus `tools/`, `resources/`, and `prompts/`). Only `index.ts` and those three folders belong there. Tools use `defineStrictMcpTool` from `server/utils/mcp/tool.ts`; it rejects unknown arguments for every tool. The protocol test registers all actual definitions through the toolkit and MCP SDK. Shared helpers live in `server/utils/mcp/` so the production build does not look for a default export on them.

```json
    "k39": {
      "url": "https://k39.online/mcp",
      "headers": { "Authorization": "Bearer $CONTENT_DRAFT_TOKEN" }

```

### Facts and verification

The fact layer writes `facts` beside the existing columns (ADR 0033); selected public readers already use the phase-2 projection. Public venue pages, venue cards, and their JSON-LD read phone, address, coordinates, and operating status from `facts` through `fact_refs`, and fall back to the column only when that fact is missing. A gap renders «уточняйте». Place pages do the same for phone, coordinates, and status. A place phone (`places.phone`) is official-only and its fact carries the source URL. Hours on venue pages, cards, and JSON-LD come from `schedules` and `schedule_intervals`, not from `venues.hours` or a copy in the description. Prose that repeats those hours or a phone is a `fact_repeated` review warning and does not block publish. Verification starts at `queue_list`. A fact whose latest revision actor is `owner` is not overwritten by the content token. That conflict waits in `/admin`. The daily source watcher claims `analytics_runs` kind `source-watch` and fetches official URLs only. Map sources are `map_yandex`, `map_2gis`, `map_google`, and `osm`, venues only. The public reader is `readShownFacts` in `apps/web-app/server/utils/facts/read.ts`.

An undated generic schedule closure reads «Закрыто», optionally followed by outside-view access. It does not imply reopening or abandonment. The shared schedule formatter preserves specific closure reasons and `until` dates in both static page details and live availability text; the wording does not change availability or stored visit status.

### Dated notices

Dated notices (ADR 0049) are the `notices` table: a relocation, a closure, a renovation, or another dated statement on a place or a venue, never a route or a collection. `notices_set` and the `/admin` place and venue forms share `setNotices` in `apps/web-app/server/utils/notices/write.ts`. The page compares `from` and `to` with today in Europe/Kaliningrad: an upcoming row shows with its dates, a row hides the day after `to`, and `expired_at` is only the hourly `notice-expire` flag for `notices_list` with `expired: true`. The hero aside «На эти даты» and the top of «Коротко» render through `TemporaryNotices`. A current `closed` row makes `OpeningLive`, venue cards, and `GET /api/public/availability` say closed without writing the schedule. A relocation address is text only: the stored address, the address fact, the pin, and JSON-LD stay. A notice is not a fact and does not change the score. The draft token on a live place or venue stages the list on `content_drafts` under `notices`; the editor `content_set_publication` with `published` (entity `venue` for a venue) applies it and keeps the publication status.

### Map rendering

Route stop legs and map distance readouts identify point-to-point Haversine measurements as «по прямой»; a stored route path does not turn a stop-to-stop label into road distance. Each surface keeps its existing rounding, focus threshold and missing-coordinate behavior. External directions links still ask the selected map service to build the actual route.

`@k39/map` is the map core (ADR 0019, visitor map page ADR 0037): basemap choice, the `paper` style, and layers for points, lines, numbered stops, and sponsored pins. The visitor map is `/map`: MapLibre GL draws one scene from that API. The server resolves the basemap at runtime. When the file at `NUXT_BASEMAP_FILE` exists and its sha256 matches `BASEMAP_SHA256`, the client receives `/basemap/kaliningrad.pmtiles` (Range). Otherwise the map uses OpenFreeMap, including when the file is missing. A background task on boot downloads `BASEMAP_SOURCE_URL` when the file is missing or the hash does not match. Those defaults are baked into the image. An https `NUXT_PUBLIC_PMTILES_URL` is an optional object-storage override. Glyphs and the sprite are on this origin. Rebuild steps are in `docs/basemap.md`. It is in the header and footer. The clean `/map` URL is registered in the sitemap source and allowed by the sitemap filter; child paths stay excluded. The map-specific SEO title avoids repeating the region. Filter queries stay `noindex` with the clean canonical. Embedded venue and route maps use the same library, loaded lazily. A route draws a solid line only from `routes.path`. Otherwise the selected route shows numbered stops and a dashed connector. Direction links on the route page stay in ADR 0015. `NUXT_PUBLIC_YANDEX_MAPS_API_KEY` does not choose a basemap.

### Eat-now proximity

`EatNowPage` renders town venue cards and centre-based distances on the server; browser hydration groups them by schedule status. Location is requested only after a button click, with a ten-second timeout and five-minute cache allowance. Pending lookup is announced. Denial, timeout and unavailable location show Russian feedback and retry; an unsupported API shows an explanation without a button. Failure retains the last successful visitor position, or the town-centre results before any success. A missing centre or venue coordinates must not become a fabricated distance. Callbacks from a previous town or an unmounted page are ignored. [S03 evidence](reviews/2026-10-23-eat-now-location/README.md) covers isolated component/browser behavior; deployed permission handling and a complete nearby-food journey still require acceptance.

### Authentication

Auth is `nuxt-auth-utils`: Yandex and VK use `defineOAuthYandexEventHandler` and `defineOAuthVKEventHandler`, and the admin session is `requireUserSession` / `setUserSession`. Empty client id or secret disables that provider. `ADMIN_EMAILS` promotes those accounts to `admin` on login. Editors and admins can open `/admin`. Anonymous visitors go to `/sign-in?redirectTo=/admin`. The session cookie is sealed with `NUXT_SESSION_PASSWORD` (32+ characters). `nuxt-auth-utils` does not read `NUXT_APP_SECRET`; switch to that when the library supports `appSecret` natively. See ADR 0005.

### Venue ownership

`/kabinet` is the cabinet behind «Войти» (ADR 0031). The same account can claim a published or closed venue. A code goes to `contact_email` or `phone` only when `CLAIM_EMAIL_URL` or `CLAIM_SMS_URL` is set; otherwise the person leaves evidence and an editor decides in `/admin/claims`. After that, the owner edits `venues.modules` with `venueModulesSchema` and `venue_prices` with the same check as `venue_prices_set` (`sourceKind` forced to `owner`). The venue schedule is the only source of venue hours, and nothing reads `venues.hours`. The cabinet and `/admin/venues/{id}` load the weekly table from it and send it only when it changed; the writer replaces the week of its one season and keeps closures, exceptions, holidays, and the source. Seasons, breaks, or another mode show read-only and change through `schedule_set`. Status, slug, and SEO stay editorial. Every save keeps a revision; `/admin/venues/{id}` can restore one. `businesses.venue_id` is the later subscription hook. The cabinet is `noindex`.

### Guest submissions

Guest submissions (ADR 0036) are a review, a tip, a photo, or a correction on a published place or venue. The public byline is the first name and the initial of the surname. Nothing is public while `pending`. `/admin/guests` accepts, rejects with a note, or flags a dispute. The editor token does the same daily pass through `guests_pending_list`, `guest_approve`, `guest_reject`, and `guest_dispute_flag` (ADR 0040). Those tools call `moderateGuest`, the same writer as the admin route. The draft token cannot. Guests cannot submit through MCP. A photo marked `recognizableFace` is rejected on that writer. A correction, including a price, only enqueues `guest_report` on `verification_queue`. It does not write facts or `venue_prices`. The separate consent is `ugc-2026-10-16` at `/gostevye-materialy`, method `ugc-submit`. Sign-in consent stays `2026-10-12`. Guest text is not in the article, the search view, or JSON-LD except a `Review` for each review that is in the HTML. Photos use `media.license = guest` and are not the cover.

### Events and analytics

`POST /api/events` requires `consent: true`, stores no IP address, and does not set a cookie. `events.session_id` is a new random id on every row, so it does not group a visit (ADR 0043; it partly supersedes ADR 0004). `useTrack()` sends nothing while `NUXT_PUBLIC_CONSENT_BANNER` is off, and no control sets the `k39_consent` cookie.

Page analytics (ADR 0013) is cookieless with the repository default consent flag off. `public/collect.js` beacons to `POST /api/collect`. The visitor key is a daily HMAC of salt, IP, and User-Agent, and the IP is not stored. `CookieNotice` is a client-only card with one button, «Хорошо». Dismiss is `localStorage` key `k39_cookie_notice`, not a cookie. `NUXT_PUBLIC_CONSENT_BANNER` defaults off; the user cabinet already exists. With that default, analytics does not set visitor cookies. The sealed authentication session is shared by users, editors and admins. Check deployment configuration separately. Raw hits last 13 months. `analytics_daily` is kept. Search queries are imported when `YANDEX_WEBMASTER_TOKEN` plus `YANDEX_WEBMASTER_HOST_ID`, or Google Search Console credentials, are set. Yandex popular queries lag about three days, so the job requests a week ending three days ago. A range through yesterday is empty even when the token is set. Read-only MCP tools `analytics_overview`, `analytics_channels`, `analytics_top_pages`, `analytics_landing_pages`, `analytics_referrers`, `analytics_search_queries`, `analytics_events`, `analytics_realtime`, and `analytics_page` are audited. The same numbers are on `/admin/analytics`.

### Scored article length

For places, routes, collections, hubs and quests, `shared/article-length.ts` measures authored text produced by the existing public Markdown renderer. Link labels count; link destinations, supported heading/emphasis/list/table syntax and generated link marks do not. Block/cell boundaries and whitespace runs count as one space, with outer whitespace trimmed. Units remain JavaScript UTF-16 code units. Unsupported Markdown and literal HTML/entities count as the renderer actually displays them.

The existing article preparation still removes a repeated place lead and folds directions into the article; collection module prose still uses its stored projection. Structured FAQ remains outside article length as before. `shared/scoring.ts` uses this one count for the floor, the effective ceiling (including a valid override), the default-ceiling filler gate and `signals.bodyChars`. Filler analysis keeps its Markdown input so section structure remains available. Catalog refresh, preview, storage and weekly reports share those signals. ADR 0016/0034 norms and justification requirements are unchanged; this corrects their public-article measure rather than raising limits. Venue descriptions retain their separate 300–600 rule. MCP save responses still report raw stored-body `bodyLength`; use score preview for scored `bodyChars`.

Existing stored scores change after the next successful daily refresh or an authorized forced refresh; no production refresh or content write is performed here.

### Content score status checks

`shared/status-consistency.ts` feeds the place-only status penalty in `shared/scoring.ts`. A bare sentence-opening closure must be a complete short form (`закрыт`, `закрыта`, `закрыто`, `закрыты`), followed by no Unicode letter; adjective and noun prefixes such as `Закрытую обувь` do not establish a closure. Existing contextual closure phrases and ADR 0045 subject handling still apply. A contradiction deducts 15 quality points; this check does not change schedules or public availability. `content_score_preview` uses the current scorer without replacing stored scores. Stored scores change on the next successful daily refresh or an authorized forced refresh; deploying a regex fix alone does not invalidate the existing daily claim. Appointment-subject behavior is tracked in [issue 294](https://github.com/hmbanan666/k39/issues/294).

### Site search

Site search (ADR 0030) is Postgres full-text (`russian`) plus `pg_trgm` over the `search_documents` view (published, indexable places, routes, collections, quests, venues, hubs, and cities with venues). Query text helpers live in `packages/database/src/search-text.ts`: normalization, wrong keyboard layout, transliteration, prefix terms. `GET /api/search?q=` is a pure read. The header form and the 404 form are plain `GET` forms to `/poisk` (server-rendered, `noindex, follow`, canonical `/poisk`). The page distinguishes pending/error from a successful empty response, preserves the query for retry and keeps the plain GET form usable without JavaScript. Retained responses from another query are hidden. Only successful responses matching the current query produce client search/click analytics; SSR, failures and pending requests do not count as zero-result searches. The page sends `search` and `click` events to `POST /api/search/events`; rows land in `search_events` with the ADR 0013 daily visitor key and session, no cookie and no IP, and are purged after 13 months. Refinements are linked server-side; exits without a click are derived in reports. Read-only, audited MCP tools `search_report` and `search_zero_results` and the page `/admin/search` show totals, top and zero-result queries joined with `analytics_search_queries`, clicks by position, surfaces, and how searching sessions arrived.

Pending collection saves validate the effective `sources` list, including lists inherited from a live row or earlier pending draft, with the same canonical source validator as publication. Duplicate URLs merge before the 24-source cap. Invalid inheritance returns 400 with origin/count and requests corrected `sources` before storing a draft or audit; it never trims a list automatically. Explicit `sources: []` clears it. A failed save preserves live and existing pending data. Publication independently revalidates legacy/raw drafts. The read-only operator report is `pnpm --filter @k39/web-app exec jiti scripts/report-source-lists.ts` with an explicitly configured `DATABASE_URL`; it never migrates or repairs content.

## Editing conventions

- Admin fetch: pages that load or save during setup use `useRequestFetch()`, as `PlaceForm.vue` does. That forwards the session cookie and the request host during server render. Do not import `ofetch` for an admin URL. A relative `ofetch('/api/admin/...')` has no base URL on the server and does not send the incoming cookie. A button handler after hydration may use `$fetch`.
- Unhead dedupes `<link>` on `rel` and `href` unless each tag has its own `key`. `brandHeadLinks` in `shared/seo.ts` keeps distinct keys for the two `favicon.ico` links.
- Facts: the claim, the column, the source kind, and the freshness window are `docs/facts.md`. Do not copy that table.

## Pages

- `/{slug}`: place. Hub, nearest, same-region, routes, collections, manual related links. JSON-LD matches the category.
- Hubs: `/forty`, `/zamki`, `/plyazhi`, `/kurorty`, `/muzei`, `/eda`. A hub stores a markdown `body`, rendered with the place article renderer. A `## Частые вопросы` section adds FAQPage. `hub_update` writes the body and the SEO fields and is audit-logged. `/admin` edits the same fields.

## Admission entry and extra lists

ADR 0050 extends the existing practical writer: `admission_set` accepts `rows` (up to 48 entry tariffs), `extras` (up to 12 paid services), or both. Omit a list to preserve it; `[]` clears only that list. Slots may repeat between lists but must be unique within one. The same admin endpoint uses this contract. Both supplied lists and their facts commit in one transaction, including fact retirement and source-watcher updates. Subject writes are serialized. A fact/source failure rolls the write back; retry is safe. A content token cannot overwrite or remove an owner-controlled fact.

Entry fields retain the five audiences and existing zero/free rules. Extras require a label and positive whole-ruble amount, have no audience, and accept `unit: person | group | device | null` (null when the official source does not say). State eligibility, group size and any required entry ticket in `condition`; do not infer inclusion. Do not encode a refundable deposit or a range as a service price. Admission sources, TTL and display freshness are in [facts](facts.md); the editor/draft-token rules remain unchanged.

`admission_get` returns entry-only `rows`, `shown`/`shownSlots`, `stored` and entry `fallback`, plus `extras`, `shownExtras`/`shownExtraSlots`, `extrasStored`, `extrasFallback` and `extrasWriteEnabled`. `admissions_list` keeps entry counters `rows`, `stale`, `oldestCheckedAt`, adds `extras`, `staleExtras`, `oldestExtraCheckedAt`, and includes extra-only subjects. `staleOnly` matches either list. An extra-only subject has null oldest entry date. Admin reads add `admissionExtras`, `shownExtraSlots`, `extrasWriteEnabled`; saving one form preserves unsaved inputs in the other.

Entry fact values/hashes are unchanged. Extra facts use kind `admission`, slot `admission-extra:{slot}` and value `{kind: 'extra', priceRub, label, condition, unit}`. `fact_update` rejects cross-variant values and goes through the same transactional writer; `fact_confirm` keeps its hash contract and updates the matching admission row check date atomically (Kaliningrad calendar date), without changing the value or adding a revision. Extra references use `short.admissionExtras`.

The public block displays «Билеты» then «Дополнительно», with each fresh row's source and check date. Entry rows alone set entry JSON-LD offers/free-access, fallback and scoring. Extras alone never suppress a legacy place price; absent entry information remains «Стоимость билета уточняйте». The same helper is used for places, venues and routes. Multi-exhibition/combined tickets are labelled entry rows; cross-subject sharing is deferred.

Extra list/value writes default off for safe server rollout; hash-only freshness confirmation remains allowed under the existing fact-confirm permissions. See [rollout and rollback](development.md#admission-extras-rollout). This switch does not hide stored public data and does not change entry writes.
