# ADR 0019: K39 map

## Status

Accepted. Supersedes the embedded basemap in ADR 0015. ADR 0002 and ADR 0009 still govern the forts booklet at `/map/forty`. The visitor map panel is specified in the UX section of `0019-visitor-map.md`.

## Context

Route pages draw a phone map (ADR 0015). Venue pages reuse that frame for one dot. A visitor should see our places, published venues, and route stops as layers, open one of our cards, and tell a partner pin from any other cafe.

The public OpenStreetMap tile server is not a production CDN, and the default raster does not match the paper and sea palette. Yandex JS needs a key that is not a required production variable, and every pan sends the visitor IP to Yandex. MapLibre would allow a custom vector style. ADR 0015 already declined that bundle for a single polyline.

A later guide map (a town, a theme, a paid walk) should be a layer we can give away or sell. That is data on our map, not a second basemap.

## Decision

### Basemap

The frame uses MapLibre GL and the OpenFreeMap Positron style, `https://tiles.openfreemap.org/styles/positron`. The data is OpenStreetMap under ODbL. OpenFreeMap serves it with no API key. CARTO's public Positron raster now paints an API-key watermark, so it is not the basemap. The style's attribution names OpenFreeMap, OpenMapTiles, and OpenStreetMap. After the style loads, those links are set to `target="_blank"` and `rel="noopener nofollow"`. A light CSS grade on the canvas warms the grey style toward the paper palette. The grade is presentation. It does not rewrite the data. Replacing the style URL does not change the page, as long as the attribution stays.

The Yandex JS API is not loaded for this frame. `NUXT_PUBLIC_YANDEX_MAPS_API_KEY` does not switch the basemap.

### Frame

The frame has a real height before the map mounts: 320px on a phone, 460px from 900px, and on `/map` `calc(100dvh - 4.5rem)` with a 420px minimum. A resize observer calls the map resize.

The library loads after the window `load` event, then `requestIdleCallback`, then an `IntersectionObserver` with a 120px root margin. Tile images are not in the first document. Scroll-wheel zoom stays off. On a coarse pointer, dragging starts disabled behind «Коснитесь, чтобы двигать карту».

### Layers

Published rows with coordinates only.

- Places. One pin per place. The glyph is shared. The card type is the category title.
- Venues. One pin per published venue. The glyph follows `kind` (cafe, restaurant, coffee, bar, bakery, market, fastfood, other).
- Route. Numbered stop pins in stop order and a line through the stops that have coordinates. The number is the route position.
- Nearby. On a place, a venue, or a route, the frame also shows our other places and published venues within 1.2 km of the current object. For a route the distance is the minimum to any stop. 1.2 km is a short walk in a straight line, the same approximation as the «около» legs. The focus pin is always drawn and is not absorbed into a cluster.

`/map` loads the catalog (capped) and lets the visitor toggle places, venues, venue kinds, and routes. It is indexable, linked from the footer, and listed in the sitemap. `/map/forty` stays the flagged forts booklet.

Clustering is a pixel grouping in this repo, redrawn on zoom. A cluster shows a count and zooms in. It is not a second map library.

### Card

A pin opens a card in the frame: photo when we have a cover, name, type, distance when the point is not the focus, a short text, a link to the page, and «Как добраться». On a small screen the card sits on the bottom edge. From 900px it sits on the side.

### Sponsored pins

When `FEATURE_SPONSORED_VENUES=true`, a venue with an `offers` row in `status = active` gets a highlighted pin. The card shows «Партнёр» and the offer text. The flag defaults off. The map payload then sends `partner: false` and no offer text, so the label cannot appear from a cached client. This is the same flag as the sponsored slot in ADR 0018. The map does not add a second way to choose the winner: any active offer on that venue highlights the pin. Later auction work can choose which offer's text is sent.

### Directions

«Как добраться» opens `https://yandex.ru/maps/?rtext=~{lat},{lon}&rtt=auto`. The coordinate is the destination. The visitor sets the origin in Yandex. The anchor uses `target="_blank"` and `rel="noopener nofollow"`. The whole-route builder on a route page stays as ADR 0015 specified it. A route stop also has its own destination link.

The click is a cookieless beacon, event type `directions`. The control carries `data-track-entity` with the public path (`/fort-11`, `/zavedeniya/slug`). The collect handler resolves that path to `place_id`, `route_id`, or `venue_id` on `analytics_hits`. The page path still fills the other id when the click happens on a route or a place. No cookie is added.

### Pin tracking

A pin impression is event type `pin_impression`. A pin click is `pin_click`. Both go through the same beacon and the same entity path, once per pin per page view for the impression (when the pin is drawn on its own, not while it sits inside a cluster). These types are not the nearby-card `impression`, so `venue_stats` does not treat a map dot as a list impression. Bots and signed-in editors are still dropped. The existing `analytics_hits` columns hold the ids. This record adds no table.

### Guide maps later

A guide map is a named set of pins on this component: same tiles, same card, same directions link, same hit rows. Giving one away or selling one is a layer and a price, not a new basemap. This record does not add the product, the payment, or a table for the layer.

## Consequences

Tile requests send the visitor IP to OpenFreeMap. The dormant consent banner does not gate that, as ADR 0015 did not gate OpenStreetMap. If that host becomes unsuitable, change the style URL and keep the attribution and the pin layers. The forts SVG map is unchanged.
